# OpsDesk 独立新版：逐步验收

新版目录为桌面 `OpsDesk`，页面为 **http://127.0.0.1:8085/**。测试账号与数据均为演示用途。实际启动命令和完整英文说明见根目录 README。

## 第一步：知识咨询

使用 `employee / local-demo-only` 登录。在「智能支持」输入：

> 如何申请业务系统访问权限？

等待「发送」按钮恢复可用。检查右侧显示 **FAQ、P3**，有知识文档引用，六个节点处理完成。工单页面不应因为这次咨询新增工单。

## 第二步：个人报修

输入：

> 我的电脑无法开机，只有我受影响。

检查 **INCIDENT、P2**。打开「工单记录」，稍等数秒后刷新，应出现对应的 `IT-...` 工单。答复完成和工具执行完成是两个阶段，允许有短暂排队时间。

## 第三步：模拟助理与重大事故

回到「智能支持」，将接入方式改为「模拟 Alexa+ 助理 / MCP」，输入：

> 全员无法访问核心业务系统，服务中断。

检查 **INCIDENT、P1**，接入方式区域显示 **MCP 2025-11-25**；工单页面出现重大事故。此界面调用真实 HTTP MCP，但属于网页模拟体验。

## 第四步：工程师交接

退出员工账号，使用 `engineer / engineer-demo-only` 登录。进入「工单记录」，找刚才的 P2 工单，填写排查记录，状态选择「处理中」并保存。然后填写解决措施，选择「已解决」并保存。

重新以员工登录，检查对应工单显示 **RESOLVED**，能看到工程师记录。已解决工单不再提供编辑表单。

## 第五步：运行与台账

以工程师登录，打开「运行与知识」，检查：

- 当前本机真实模型方案：数据库 `mysql`、Redis 已连接、向量索引 Ready。
- 工具队列包含 `create_work_order`、`export_ledger`，P1 还包含 `notify_escalation`，最终均为 DONE。
- 审计中传输为 `mcp`，通知回执为 `mode: record`、`status: recorded`。
- 下载 Excel 台账，至少能找到刚才两条故障工单；同一操作 ID 不应重复出现。

「规则演示」模式不验证真实模型和向量服务。若真实模式出现降级提示，需要查看诊断并修复后再将完整技术链路作为验收通过。

## 第六步：知识导入

创建一个纯文本或 Markdown 测试文件，写入自行编写的办公 IT 指引。上传后文档列表应显示文件名和片段数。真实向量模式需要点击「重建向量索引」，确认 Ready 后再咨询该指引。PDF 仅支持可提取文字的文件，扫描件没有 OCR。

## 自动验证

在项目目录执行：

```bash
.venv/bin/python -m pytest -q
.venv/bin/python scripts/verify_live.py --require-real
.venv/bin/python scripts/evaluate.py
```

真实链路脚本会创建合成工单并记录处理结果。原型项目 8083 的数据库与内容不会被该脚本修改。
