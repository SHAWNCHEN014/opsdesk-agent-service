## 面试：项目动机

“我关注的是员工只描述一个现象，而 IT 工程师需要影响范围、依据和处理记录之间的衔接问题。我做了一个本地可复现的智能服务台：咨询只给指引，真实故障才进入工单，重大中断记录升级。参赛方向选择 Alexa+ 的模拟助理路径，用真实 MCP 把自然语言入口接到同一业务闭环。”

提交前将最后一句说成“按该赛道准备”；提交后可说“作为该赛道参赛作品提交”。不声称已接入官方 Alexa 设备。

## 面试：是不是多 Agent？

“这是由任务图协调的多角色 Agent 工作流。理解、分级、生成、审查四个角色使用同一个 Qwen3-8B，通过不同指令和结构化输出承担各自职责；检索和记忆是工具节点。理解、检索和记忆可以并发，后续按照依赖推进。它不是六个独立模型，也不是任意自主协商的通用自治系统。”

## 面试：Harness 做什么？

“请求入口负责身份、会话归属、敏感字段遮盖、操作 ID 去重、持久化和 SSE。任务图负责节点依赖、输出与时延记录。模型返回后先审查最终文本，再向用户发布；副作用交给持久化队列，避免模型直接写台账或随意执行命令。”

## 面试：为什么两套 MCP？

“外部 Streamable HTTP 负责跨应用支持请求和进度查询，按登录身份限制归属。内部 stdio 把创建工单、台账、通知记录做成允许列表工具。队列只传已落库的操作 ID，工具再核验是否有资格执行。同一请求重放不会重复创建工单或台账。”

## 面试：数据与指标如何解释？

- 20 项测试是这个新版本的真实输出。
- 真实模型验证是三个合成业务请求、12 次角色调用；不代表广泛模型准确率。
- 24 条分类样例仅测确定性回退规则，不能称为模型测试集。
- 12 条检索样例的 HitRate@4 为 1.0，MRR 为 0.9583，规模小且自行编写，一页简历推荐写样例规模即可。
- 6 个 Skills 和 6 份双语知识文件由本次独立编写，未复用旧资料。
- 记忆摘要是有界抽取，重排是查询相关度规则；没有另一个摘要模型或 Cross Encoder。
- 通知是本地记录，未验证真实外发邮件；没有 LoRA、AWS 运行时、企业 SSO、生产用户或节约工时数据。
